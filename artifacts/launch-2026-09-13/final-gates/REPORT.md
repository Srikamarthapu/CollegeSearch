## Findings and fixes

1. **Long student notes could not scroll normally with the mouse.** A 1,247-character synthetic Activities note had a 598px scroll height and 118px viewport. Before the fix, a wheel action left its scrollTop at 0 and moved the page from field top 320px to -337px. After exempting native textareas from Lenis interception, scrollTop reached 480px while its top stayed exactly 299.921875px. The prior 70-character local QA entry was restored; the previously empty private guest field was also restored. No student data was used.
2. **Notebook restore previews lacked keyboard access and native nested scrolling.** Before the fix, the long list was not in the tab order and wheel input moved the document. The preview now receives guarded heading focus, the list retains list semantics and has a named keyboard stop, and Cancel returns focus to Restore notebook backup. A synthetic 50-notebook file preview identified 47 addable notebooks and protected three existing local notebooks. Tab + PageDown scrolled the list 220px; a wheel action reached 940px while list top stayed 479.8515625px. The preview was cancelled without restoring fixture entries. The guest shortlist stayed empty.
3. **The data-health page lacked an overdue published-verification warning.** The page and operations probe now share a 192-hour policy. A per-request server render shows current, overdue, incomplete or unavailable verification status. The text distinguishes artifact availability/fingerprints from reporting periods and manual factual review. The compiled Worker was tested twice in the same process with a controlled clock: seven days returned current, nine days returned the overdue warning, with private/no-store headers. The exact 192-hour boundary, rounding and future/malformed timestamps are covered. No production timestamps were changed. At a 320px viewport, client and scroll width both measured 305px (the remainder is the browser scrollbar); no horizontal overflow was observed.
4. **A revoked session could falsely confirm an empty shortlist.** See `session-finding.md`. The actual private browser showed an empty “up to date” account while its three database rows remained. The adapter now verifies the same captured JWT before and after accepting any real read or mutation. Failure preserves the complete cache and durable pending intent. Manual Retry sync protects volatile intent, then reverifies Auth and rebuilds the captured session. The local browser retest showed Davis and Irvine plus an explicit “1 change pending” notice while the database retained all three colleges. Retry moved to the guest sign-in state. Signing back in replayed the single pending Berkeley removal and produced an up-to-date two-college list matching the database. The original private page reload also correctly signed out, and its second tab followed the sign-out event without a manual reload. This tests revocation; natural token expiry remains distinct.
5. **The repeatable smoke probe omitted My deadlines.** `/plan` is now required. A successful smoke run has 16 requests. The failure regression explicitly returns 503 for `/plan` and requires the probe to fail. Older 15-request reports are historical evidence and were not rewritten.
