# M3 private adviser SQL verification

Verified October 4, 2026 in `collegesearch_m3_verify`, a separate restore of the legacy baseline inside the locally owned Docker container `collegesearch-goal-db-20261004`. The container has no network and no published ports. The M3 migration and synthetic Auth/session fixtures were applied only to this clone; the default database, M2 verification database, and hosted Supabase project were not modified.

The repeatable SQL fixture is `tests/fixtures/m3-seed-adviser-users.sql` followed by `tests/fixtures/m3-verify-private-adviser.sql`. The latter runs in one transaction and rolls back all quota, message, conversation, session-revocation, and account-deletion test data. It passed with `psql -X -v ON_ERROR_STOP=1`; the log is ignored at `work/m3-verify.log`.

The checks confirmed that public RPC wrappers are `SECURITY INVOKER`, executable only by `service_role`, and unavailable to `PUBLIC`, `anon`, or `authenticated`. Private mutation helpers are narrowly executable by the service role. Anonymous users cannot read private adviser tables. Authenticated users can read only their active-session conversation, messages, and quota; they cannot write content, read request/idempotency rows, alter quota, or invoke service RPCs. Service-role table grants cover server-side persistence.

The reservation tests rejected null limits and wrong-session requests. Atomic per-user busy handling blocked a second live request. Three released provider attempts exhausted a one-success retry budget, and the global cap also counted a failed attempt. A same-body completed retry returned its cached answer; changing the body for the same key returned `conflict`. After lease expiry, the retry received a new lease; stale completion and release operations could not affect it. Wrong-session and revoked-session completion both returned false.

Deleting a conversation as its owner cascaded its messages, cleared the cached answer, and left a content-free `deleted` idempotency tombstone. The successful/attempted quota row remained unchanged, and replay returned the deleted status. Expired transcripts were hidden before purge; after the simulated 90-day age, purge deleted the conversation, messages, and old request tombstone while leaving the user's quota row. Deleting an Auth user removed its private conversations, messages, requests, and quota.

The verification found two defects in the first migration draft and re-ran after fixes: the erasure trigger now skips tombstone updates while the parent Auth user is already cascading, and title generation removes POSIX control characters before truncating. The regression message included U+0001, newline, tab, and more than 80 characters; the stored title was clean and bounded.

Concurrent completion versus owner deletion was exercised by `tests/fixtures/m3-concurrent-delete-complete.mjs`. The harness commits test state only in the isolated M3 clone: an authenticated deletion held the conversation lock while a second connection attempted completion. Completion returned false, both transactions finished without deadlock, messages and cached response were erased, and the request remained as a tombstone. The log is ignored at `work/m3-concurrent-race.log`. Recreate the clone from the baseline before repeating because this race test intentionally commits its synthetic reservation/deletion.

This SQL verification does not prove NIM availability, model answer quality, provider timeout behavior, browser account deletion flows, or production retention scheduling. The provider call remains subject to the separate NVIDIA production-permission gate, and the scheduled 90-day cleanup route still needs its own application/host verification.
