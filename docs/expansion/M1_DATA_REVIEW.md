## Findings

### Tuition needs a residency-aware label

The existing observations keep tuition and net price as separate facts, but the generic `tuitionInState` / `tuitionOutOfState` fields overstate what the federal source says. The Scorecard Technical Documentation, Costs section (September 2025, PDF p. 13), defines `TUITIONFEE_IN` as **in-district** tuition and required fees, says some schools' in-state prices are not reflected in that metric, and defines `TUITIONFEE_OUT` as out-of-state. The [official Scorecard documentation](https://collegescorecard.ed.gov/assets/InstitutionDataDocumentation.pdf) supports treating the first metric as an in-district baseline when sourced from College Scorecard, not as a verified in-state price.

IPEDS's [2023–24 tuition table](https://nces.ed.gov/ipeds/search/viewtable?returnUrl=%2Fsearch&tableId=36557) presents in-district, in-state, and out-of-state columns for public schools, but a single private-school price column; its footnote says out-of-state tuition was used for all private institutions. The current worktree's [tuition-label helper](../../app/lib/tuition-labels.ts) shows public federal `TUITIONFEE_IN` as in-district and one published price for private schools. The refreshed generated observation definition identifies the federal field as in-district, and the source-value audit confirms its numeric value matches the pinned ZIP. Keep the underlying observation's publisher, period and exact source field attached. The legacy JSON key remains `tuitionInState`, so consumers should use the source-aware label rather than infer residency from that key.

The refreshed worktree contains source-aware tuition presentation: College Scorecard `TUITIONFEE_IN` is labeled in-district, public schools retain separate federal in-district and out-of-state rows, and private schools show one published tuition-and-fees value. For a new catalog record, display an in-state price only when its source explicitly reports that rate; otherwise retain the federal in-district label and note that the student's residence classification should be checked with the institution.

IPEDS defines cost of attendance as tuition and required fees, books and supplies, housing/food, and other expenses. Average net price subtracts grant and scholarship aid from this broader attendance cost for a specified aid cohort. It is not tuition, not a full cost-of-attendance figure, and not a personalized estimate. The [NCES net-price FAQ](https://nces.ed.gov/ipeds/report-your-data/faq-average-net-price) and [IPEDS survey methodology](https://nces.ed.gov/ipeds/survey-components/ipeds-survey-methodology) support the current product's distinction between its “Average net price” and “tuition + required fees” rows. Keep those metrics separate in the adviser and any new cost filters.

### Population, cycle and campus scope must survive import and display

- College Scorecard `ADM_RATE` is an institutional Fall admission rate for first-time, degree/certificate-seeking undergraduates. It does not describe transfer admission or major-level selection. Scorecard distinguishes a campus value (`ADM_RATE`) from a system-wide multi-branch value (`ADM_RATE_ALL`); keep the fact bound to the same UNITID campus identity used for the profile. [The current importer selects `ADM_RATE` and records the population](../../scripts/import-scorecard.mjs#L489-L500). The IPEDS [Admissions component](https://nces.ed.gov/ipeds/survey-components/6) documents that its applicant/admit/enrollee data covers entering first-time degree/certificate-seeking undergraduates and is not collected from open-admission institutions. Label these as institutional first-time/first-year evidence; do not infer transfer rates, program rates, or personal odds.
- UC records intentionally combine preliminary Fall 2026 applicant/admit counts with finalized Fall 2025 enrollees and yield. This distinction is recorded in the release notes and on each observation in [the generated dataset](../../data/colleges.json#L1-L80). The profile shows a period under each admission value and cohort/source in its disclosure. Keep that prior-cycle yield warning visible when refreshing; never divide Fall 2025 enrollees by Fall 2026 admits or imply that the UC values form one cohort.
- Scorecard graduation `C150_4` is a 150%-of-normal-time completion measure for a first-time, full-time degree/certificate-seeking cohort at a four-year institution, not a graduation rate for all students or for transfers. Keep the entering-cohort year next to the value. [IPEDS cohort definitions](https://nces.ed.gov/ipeds/use-the-data/student-cohorts-and-subgroups) explain the population.
- `UGDS` has a specific Scorecard definition: fall enrollment of degree/certificate-seeking undergraduates. [Scorecard documentation](https://collegescorecard.ed.gov/assets/InstitutionDataDocumentation.pdf) documents that field. Preserve it as a fall count, not total headcount across every enrollment category.
- **Correction to the initial delivery interpretation:** I previously described the code-2 subset as “exclusively-distance” and treated each broad two-digit CIP field as online-only. That was inaccurate. The official [College Scorecard institution documentation](https://collegescorecard.ed.gov/files/InstitutionDataDocumentation.pdf) explains in the Academics section (PDF p. 9, footnote 12) that a broad two-digit CIP category can aggregate several six-digit programs and is flagged for distance education when at least one program in that broad family is distance-only. Therefore code 2 supports “includes a distance-only program”; it does not support saying the whole broad field is online or that campus options are absent. The refreshed data uses `deliveryMode: "includes-distance-program"` and matching caveat text. The independent audit checked all 1,152 generated broad-field pairs and rejects copy that overstates a code-2 value as applying to the entire field. A missing broad-field record means “not listed in this evidence set,” not “the institution does not offer the program.”
- Preserve UNITID as the campus key. Keep OPEID (campus-level aid identifier) and OPEID6 (institution/system aid identifier) distinct; Scorecard documentation notes that some NSLDS and Treasury metrics are rolled up or averaged across a shared OPEID6. Do not join observations, sources, or program claims by institution name alone.

### Validation coverage is useful but layered

The initial generated baseline contained 50 unique UNITIDs and 29 registered sources. The refreshed release contains 100 colleges. The federal Scorecard artifact remains pinned by release URL and SHA-256 in `release.sources`; per-fact `sourceField` and `UNITID` provide the field/row locator. The `assertCollegeEvidence` validation in [college-evidence.ts](../../app/lib/college-evidence.ts) checks metric units, value/status consistency, dates, lineage and source-registry URL/publisher binding for primary and alternate observations. Those checks catch malformed or unregistered evidence, but cannot prove that a source supports an entered number. The separate [federal value audit](M1_FEDERAL_VALUE_AUDIT.md) performs that field-and-row comparison for Scorecard-backed values.

Institution overlays have a separate, stronger schema in [institution-overlays.mjs](../../scripts/lib/institution-overlays.mjs): unique UNITIDs and source IDs, allowlisted registered sources, value ranges, and arithmetic/context consistency for derived admissions and yield. Its online verifier checks HTTPS and redirects, allowed hosts, response size/type, file signature or reviewed HTML anchors, and approved hashes in [verify-institution-overlays.mjs](../../scripts/verify-institution-overlays.mjs). A matching hash proves the reviewed artifact is unchanged; it does not re-review every fact or make an older reporting period current. This limitation is also stated in [the verification guide](../data-source-verification.md).

At the initial review, the checked-in 26-artifact verification snapshot was stale. After the refresh and content review, the parent task reports that live source verification passes **26/26 artifacts**. The earlier 50-record evidence-test failures for missing catalog metadata are historical; the catalog reviewer reports that the expanded artifact passes `assertCollegeEvidence`. This report's independent Scorecard audit is an offline exact-value check. It does not replace the live artifact verifier or application and rendered-flow checks.

The refresh now uses the reviewed catalog manifest as its exact UNITID roster and retains the original 50 institution identities; the 100-record manifest check covers all U.S. states and DC, and `censusRegionForState` fails on unknown state codes. The importer validates each Scorecard row's name, state, ownership code, main-campus status, operating status, degree level, and branch count against that manifest before output. Manifest ownership codes are restricted to public and private nonprofit (Scorecard `CONTROL` 1 and 2), which fits the curated cohort; although the generic label helper has a private-for-profit fallback, an unreviewed code cannot pass manifest row validation. The independent audit compared the generated campus identity fields for all 100 UNITIDs.

## M1 close-out status for the expanded release

The repeatable [federal value audit](M1_FEDERAL_VALUE_AUDIT.md) checks the ZIP SHA against catalog and generated release registrations, exact manifest/dataset UNITID coverage, official campus identity fields, each direct Scorecard primary and alternate observation, and each generated broad-field award share and bachelor's availability code. The 100-record canonical dataset passes with 800 direct metric comparisons, 1,152 broad CIP pairs and zero errors. The parent task reports that the transactional refresh and live artifact verification also completed successfully.

The remaining work for overall product acceptance is in the parent task: full test/build checks and rendered profile/comparison review for tuition, cross-year UC admissions/yield, and broad-field distance caveats. This audit does not directly validate UC and first-party institution values, cohort wording, source freshness, or actual rendered behavior. Keep suppressed/missing values unavailable rather than filling them with zero or carrying a neighboring campus's value.

If a source artifact changes, the existing correction path is fail-closed: manually inspect the official source, update the source fingerprint/review notes and affected fact only after comparing the cited field/row/page, run offline schema tests, run online artifact verification into a fresh report, then publish all generated data in the staged refresh transaction. Automated hash success alone does not approve a correction. The expanded release should also maintain a small correction/review ledger containing UNITID, metric, prior/new source and values, reviewer, review date and reason; the current overlay has review notes and git history but no uniform field-level correction ledger.
