# M6 local authentication verification

Verified October 4, 2026 against the project's isolated Supabase CLI stack and local Next app. These checks used only disposable `example.test` identities, the local loopback API, and local Mailpit. No hosted Supabase project or real recipient was used. After browser and API checks finished, the synthetic browser account was deleted and the local Supabase stack was stopped with its data volumes preserved.

## Local stack and fixture

The local Supabase stack ran on `127.0.0.1:55321` (API/Auth), `127.0.0.1:55322` (Postgres), and `127.0.0.1:55324` (Mailpit UI). The project was unlinked from hosted Supabase and all five repository migrations were applied locally with `db reset --local --no-seed`. The Next review server used its separate ignored build directory and loopback app port 3000. The Supabase CLI then stopped only project `CollegeSearch` with its normal backup-preserving stop command; no `--no-backup` or machine-wide `--all` option was used. The local project volumes remain. Generated local keys and the synthetic password were kept in mode-600 files under ignored `work/local-auth/`; no credential values were copied into this report.

A confirmed synthetic browser account was provisioned with one synthetic adviser conversation, two clearly marked synthetic messages, and one completed request. The parent browser session signed in through the local app and opened the prepared conversation. No adviser-provider request was made.

## Results

- `scripts/verify-account-integration.mjs` passed all six live local Auth/PostgREST checks: current-session validation, owner save/read, cross-user read/write denial, anonymous denial, global session revocation blocking stale-token RLS access, and account deletion/cascade. Its two temporary test users were deleted. The harness used the local API URL exactly `http://127.0.0.1:55321`; it did not invoke the hosted account-deletion endpoint.
- The signed-in adviser history API returned the owner’s conversation and both messages. A disabled-mode POST returned 503 before quota reservation; adviser conversation, message, and request counts were unchanged. This verifies the honest no-provider state and zero-write boundary, not successful inference. The local app's configured origin is `http://localhost:3000`; its same-origin POST check passed with that Origin, while `http://127.0.0.1:3000` was rejected as a mismatch.
- A separate public sign-up against local Auth began unconfirmed and without a session. Mailpit captured the confirmation email. Following its local Supabase verification link set `email_confirmed_at` and redirected to the allowlisted loopback `/auth/callback`. The temporary sign-up account was deleted afterward; its captured message remains in the local Mailpit inbox for inspection.
- The CUA-saved college, UNITID `110486`, was visible through the owner's authenticated PostgREST request and agreed with the local service-role database view. The actual local adviser `DELETE` API then removed only the synthetic fixture conversation. A follow-up owner GET returned 404; the conversation and its two messages were gone; the completed request remained as a `deleted` tombstone with its cached response cleared. UNITID `110486`, the synthetic account, and its active session remained intact.
- In the local signed-in browser, the parent also saved a task due November 11, 2026. Filling the date field alone did not commit its React state; an ArrowUp keyboard action did, and the task persisted after reload alongside the account notebook and saved college. After the adviser deletion, the history view was empty and the browser signed out successfully. Guest isolation showed no saved colleges, tasks, or notebook. No product code change was needed for the date field.
- After those checks, only the synthetic browser Auth user was deleted. Admin readback confirmed the Auth user no longer exists and zero owner rows remain in `saved_colleges`, `adviser_conversations`, `adviser_messages`, `adviser_requests`, and `adviser_usage_periods`. The separate confirmation email remains captured in the preserved local Mailpit volume.
- Separate database rehearsal reports cover the broader SQL/RLS cases: [M0 foundation results](M0_FOUNDATION_RESULTS.md), [M2 knowledge SQL verification](M2_SQL_VERIFICATION.md), and [M3 private adviser SQL verification](M3_SQL_VERIFICATION.md). Those isolated Docker-clone checks cover saved-row ownership, anonymous and revoked-session access, private-table grants, quota reservation/idempotency, deletion and expiry, and concurrent completion/deletion. They did not modify the default database or hosted project.

Machine-readable summaries are in ignored `work/local-auth/account-integration.report.json`, `work/local-auth/local-signup-mail.report.json`, `work/local-auth/cua-save-delete.report.json`, and `work/local-auth/browser-user-cleanup.report.json`. The adviser API summary is in the ignored, mode-600 `work/local-auth/adviser-api.private.log`. Test scripts in `work/local-auth/` intentionally are not part of the product source.

## Limits and remaining checks

It does not verify hosted sign-in, production email delivery or recovery, a hosted signed-in account journey, browser-based account deletion, production provider calls, or semantic model quality. The adviser remains disabled and no NVIDIA key was used. Hosted unauthenticated routes and SQL policy checks are recorded in [the hosted release report](M4_HOSTED_RELEASE.md); hosted signed-in Auth and email checks remain outstanding.
