# Institutional source verification

`node scripts/verify-institution-overlays.mjs` checks all 26 registered institutional artifacts and writes `data/institution-source-verification.json` atomically. Every available result is recorded before a nonzero exit; a first failure no longer hides failures in later sources. `--report <path>` or `INSTITUTION_VERIFICATION_REPORT_PATH` can override the report destination. `INSTITUTION_OVERLAYS_PATH` selects a read-only reviewed manifest. The function API writes only when passed `reportPath`.

The report distinguishes `checkKind: artifact-integrity` from manual factual review. A passed source means the live artifact passed the existing HTTPS/host, redirect, size, MIME/file-signature and approved fingerprint checks. It does not establish a newer reporting period, current individualized admission odds or net price, or a new factual review of every field. `lastApprovedEvidence.reviewedOn` remains the approval date; automated verification does not alter it or the overlay. `artifactHashMode` says whether a fingerprint is raw or explicitly normalized HTML. Expiring Box download URLs are not persisted in the report; `finalHost` records the final download host.

`status` is `passed` or `failed` at report level. Per-source statuses are `passed`, `failed` or `not_checked`; the last status is used if the aggregate byte budget is exhausted. `schemaStatus: failed` and a top-level `error` distinguish invalid input from a zero-failure source run. An offline check uses `checkKind: offline-schema` and must never be presented as a successful live check. The CLI does not overwrite the live report during ordinary `--offline` use.

The existing `scripts/refresh-data.mjs` remains fail closed. It verifies the staged copy of the reviewed manifest before imports, checks the manifest did not change before publication, validates the exact 50-college cohort, and retains lock/rollback publication behavior. The operational report is written independently of the generated-data transaction so failures survive while the last known good college data remain usable.

The weekly/manual GitHub workflow deletes its checkout's old report before checking, writes a job summary and uploads the newly generated report even when verification fails. Dependency/setup failures cannot upload an older checked-in report as a fresh result. The workflow never approves changed evidence or changes the dataset. Failed sources require review against their official publisher's current page before updating URLs, allowed hosts, hashes, notes or observations.

The app's imported JSON is a **published verification snapshot**, not a live connection to the scheduler. Display its exact checked-at time, last factual-review date, and stale/failed states. A future weekly workflow artifact does not automatically update a previously deployed build. Maintain this distinction unless a separately reviewed report-publication mechanism is added. Workflow artifacts and run summaries provide maintainer monitoring immediately; refresh/review commits carry a new snapshot into the next deployment.

On 2026-09-13 all 26 artifacts passed; all 28 observations attached to the six repaired registrations were manually rechecked. The other 20 fingerprints matched previously reviewed artifacts and keep their earlier factual-review dates. The full real refresh rebuilt all 50 colleges from official downloads, with no numerical/cohort changes. See the launch handoff's logs and review decisions for exact source findings.
